## Контекст задачи

Codex Token Monitor — это self-hosted Flask-like HTTP сервер + browser frontend для парсинга и визуализации Codex rollout JSONL (сессионные логи AI-ассистента). Показывает стоимость сессий, шагов, внутренних запросов модели.

**Handoff 0051** исправляет смысл "стоимости видимого шага": разделяет `request cost` (один внутренний запрос) и `full visible step cost` (сумма всех запросов между сообщениями пользователя).

В процессе правок всплыли проблемы:
1. apply_patch (custom_tool_call) — не извлекались имена файлов из патч-текста
2. update_plan классифицировался как "диагностические команды"
3. cost семантика вводила в заблуждение (tool output chars ≠ AI cost)
4. Нужны forensic-grade details: patch_input_chars, tool_output_chars, статус success/failed

## Что нужно проверить

### 1. apply_patch file extraction и статус
Функция `_extract_patch_target_files` (server.py ~line 888) извлекает имена файлов из `*** Update/Add/Delete File:` в custom_tool_call arguments. Linker (server.py ~line 2743) определяет `patch_status` из output-текста.

Вопросы:
- Корректно ли извлекаются файлы из разных форматов custom_tool_call payload?
- Правильно ли определяется failed vs success статус?
- Достаточно ли надёжен fallback-поиск по всему pl payload?

### 2. Cost семантика в UI
`buildTimelineItemDetails` (app.js ~line 1910) показывает для apply_patch: patch_input_chars, tool_output_chars, cost_note_ru. Нет ли мест, где tool_output_chars представлен как "стоимость файла"?

### 3. plan_update и model_only
`_classify_service_call` (server.py ~line 1078) и `buildTimelineItemDetails` обрабатывают update_plan и ai_call_only. Корректно ли?

### 4. Data flow
Данные проходят: event parser → linker → tool_groups → _build_agent_activity → _enrich_timeline_items → frontend render. Нет ли разрывов в цепочке данных?
